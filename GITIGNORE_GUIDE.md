# .gitignore Configuration Guide

## Overview

This project uses a multi-level .gitignore strategy to ensure unnecessary files and folders are not tracked by Git.

---

## File Structure

```
.
├── .gitignore                    # Root level (applies to entire project)
├── frontend/.gitignore           # Frontend specific
├── backend/.gitignore            # Backend specific
└── backend/uploads/.gitkeep      # Preserves uploads directory
```

---

## What's Being Ignored

### 1. Dependencies ✅

**Ignored:**

- `node_modules/` - All npm packages
- `**/node_modules/` - In any subdirectory

**Why:**

- Large folder (100+ MB)
- Can be regenerated with `npm install`
- Different per environment

**To restore:**

```bash
# Frontend
cd frontend
npm install

# Backend
cd backend
npm install
```

---

### 2. Build Outputs ✅

**Ignored:**

- `dist/` - Production build
- `build/` - Alternative build folder
- `.vite/` - Vite cache

**Why:**

- Generated files
- Can be rebuilt with `npm run build`
- Different per environment

**To restore:**

```bash
# Frontend
cd frontend
npm run build

# Backend (if applicable)
cd backend
npm run build
```

---

### 3. Environment Variables ✅

**Ignored:**

- `.env` - Main environment file
- `.env.local` - Local overrides
- `.env.*.local` - Environment-specific locals

**Why:**

- Contains sensitive data (API keys, passwords)
- Different per environment
- Security risk if committed

**To setup:**

```bash
# Frontend
cd frontend
cp .env.example .env
# Edit .env with your values

# Backend
cd backend
cp .env.example .env
# Edit .env with your values
```

---

### 4. Log Files ✅

**Ignored:**

- `*.log` - All log files
- `npm-debug.log*`
- `yarn-debug.log*`
- `yarn-error.log*`

**Why:**

- Generated during development
- Can be large
- Not needed in repository

---

### 5. OS Files ✅

**Ignored:**

- `.DS_Store` - macOS folder metadata
- `Thumbs.db` - Windows thumbnail cache
- `desktop.ini` - Windows folder settings

**Why:**

- OS-specific
- Not needed for project
- Clutters repository

---

### 6. IDE Files ✅

**Ignored:**

- `.vscode/` - VS Code settings
- `.idea/` - JetBrains IDE settings
- `*.swp`, `*.swo` - Vim swap files

**Why:**

- Personal preferences
- Different per developer
- Not needed for project

**Note:** If you want to share IDE settings, create a `.vscode/settings.json.example` file.

---

### 7. Test Coverage ✅

**Ignored:**

- `coverage/` - Test coverage reports
- `.nyc_output/` - NYC coverage data

**Why:**

- Generated by tests
- Can be regenerated
- Large files

**To restore:**

```bash
npm test -- --coverage
```

---

### 8. Uploads Folder ✅

**Special Case:**

```
backend/uploads/
├── .gitkeep          # ✅ Tracked (preserves folder)
└── *                 # ❌ Ignored (all uploaded files)
```

**Why:**

- Uploaded files can be large
- User-generated content
- Different per environment

**Setup:**

- Folder structure is preserved
- Actual uploads are ignored
- `.gitkeep` ensures folder exists

---

### 9. Temporary Files ✅

**Ignored:**

- `*.tmp` - Temporary files
- `*.temp` - Temporary files
- `.cache/` - Cache directories

**Why:**

- Temporary by nature
- Not needed in repository

---

### 10. Documentation Files (Optional) ⚠️

**Currently NOT ignored, but can be:**

Uncomment these lines in `.gitignore` to ignore documentation:

```gitignore
# Documentation markdown files
**/*_GUIDE.md
**/*_SUMMARY.md
**/*_IMPLEMENTATION.md
**/*_COMPLETE.md
**/*_FIX.md
**/*_STATUS.md
**/*_REFERENCE.md
**/*_VISUAL_GUIDE.md
**/*_QUICK_REFERENCE.md
**/README_*.md
```

**Examples of files that would be ignored:**

- `LOADING_STATES_COMPLETE_GUIDE.md`
- `ADVANCED_TABLES_VISUAL_GUIDE.md`
- `SIDEBAR_QUICK_REFERENCE.md`
- `TOAST_FIX_SUMMARY.md`
- `README_RICH_TEXT.md`

**Why you might want to ignore:**

- Many documentation files (50+)
- Generated during development
- Can be regenerated if needed

**Why you might want to keep:**

- Useful for team members
- Documents implementation decisions
- Helps with onboarding

## Common Issues

### Issue 1: File Already Tracked

**Problem:** File is in .gitignore but still showing in git status

**Solution:**

```bash
# Remove from git tracking (keeps local file)
git rm --cached filename

# Or for a folder
git rm -r --cached foldername/

# Commit the removal
git commit -m "Remove tracked file from git"
```

### Issue 2: node_modules Still Tracked

**Solution:**

```bash
# Remove from git
git rm -r --cached node_modules/

# Commit
git commit -m "Remove node_modules from git"
```

### Issue 3: .env File Committed

**Solution:**

```bash
# Remove from git (KEEP LOCAL FILE!)
git rm --cached .env

# Commit
git commit -m "Remove .env from git"

# Make sure .gitignore includes .env
echo ".env" >> .gitignore
git add .gitignore
git commit -m "Add .env to gitignore"
```

## Best Practices

### 1. Never Commit Sensitive Data ⚠️

**Never commit:**

- API keys
- Passwords
- Database credentials
- JWT secrets
- Private keys

**Use instead:**

- `.env` files (ignored)
- `.env.example` files (tracked, with dummy values)

### 2. Keep .gitignore Updated

**When adding new tools:**

- Check their documentation for .gitignore recommendations
- Add patterns to .gitignore before committing

### 3. Use .gitkeep for Empty Folders

**Example:**

```bash
# Create folder
mkdir backend/uploads

# Add .gitkeep
touch backend/uploads/.gitkeep

# Add to git
git add backend/uploads/.gitkeep
```

### 4. Review Before Committing

```bash
# See what will be committed
git status

# See what's ignored
git status --ignored

# Review changes
git diff
```

## Cleaning Up Repository

### Remove all ignored files from git:

```bash
# Remove all files from git index
git rm -r --cached .

# Re-add all files (respecting .gitignore)
git add .

# Commit the cleanup
git commit -m "Clean up repository - remove ignored files"
```

**⚠️ Warning:** This will remove ALL files from git tracking temporarily. Make sure you have a backup!

## Verification Checklist

After setting up .gitignore, verify:

- [ ] `node_modules/` is not tracked
- [ ] `.env` files are not tracked
- [ ] `dist/` and `build/` are not tracked
- [ ] `.vite/` is not tracked
- [ ] Log files are not tracked
- [ ] OS files (.DS_Store, Thumbs.db) are not tracked
- [ ] `backend/uploads/` folder exists but files are ignored
- [ ] `.gitkeep` file is tracked

**Check with:**

```bash
git ls-files | grep -E "(node_modules|\.env|dist|\.vite|\.log|\.DS_Store)"
```

Should return nothing if properly ignored.
